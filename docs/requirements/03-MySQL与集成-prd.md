# 分布式即时通信平台｜MySQL 数据与集成

## 持久化边界

MySQL 8.4 InnoDB 是本项目业务状态与授权关系的权威存储。租户身份进入业务唯一键与关联检查。媒体、文件、备份或模型大对象允许使用文件或对象存储，库内保存版本化引用、长度、摘要及所有者。派生缓存可从持久记录重新构建。

## 逻辑实体与事实来源

| 业务域 | 核心实体与必要字段 | 写入时必须维持的规则 |
|---|---|---|
| 应用与身份 | app(tenant,key), device_session(user,device,expires) | 服务端从凭据解析租户，设备令牌独立轮换，撤销生效后终止对应连接。 |
| 接入与路由 | connection(device,epoch,node), presence(user,last_seen) | 记录设备的连接代际；新连接替换旧连接时延迟到达的断开事件只影响旧代际。 |
| 会话与群组 | conversation(tenant,kind,key), membership(thread,user,from_seq,to_seq) | 私聊身份规范排序去重，群成员的可见序号区间决定能否取历史或媒体。 |
| 发送与排序 | message(thread,seq,client_id,hash), outbox(message,state) | 给客户端成功前保存消息及分发意图；相同身份不同载荷返回冲突，群内顺序按服务端序号。 |
| 离线同步 | inbox(user,thread,high_seq), sync_cursor(device,thread,seq) | 通知只是提示，历史同步按持久记录补拉。过期缺口返回最早可取边界。 |
| 多端阅读 | read_state(user,thread,last_seq), device_cursor(device,last_seen) | 游标只允许向前且不越过用户可见水位，未读排除本人消息，重读不重复计数。 |
| 媒体与治理 | attachment(tenant,digest,owner), retraction(message,actor,at) | 附件引用前检查归属与完成态，撤回用占位事件保留顺序，下载前验证成员关系。 |
| 运维与容量 | queue_stat(tenant,node,window), delivery_attempt(message,device,status) | 区分接收、落库、分发和客户端确认，慢设备降级为补拉，保留积压年龄与重连指标。 |

## 事务、索引与对账

- **身份与约束**　会话＋序号与发送账户＋设备＋客户端号分别唯一，客户端消息号的作用域写入 SDK 契约。
- **业务索引**　会话＋序号分页补拉，用户＋会话读取已读水位，设备＋代际定位活动连接。
- **数据生命周期**　附件链接短期有效，过期历史以可识别缺口返回；租户可导出保留策略执行结果。

同会话分配序号、写消息和分发任务同事务；按发送者及客户端消息号去重，已读只接受更大的可见序号。

列表使用租户、业务状态、更新时间和稳定主键分页。外部事件保留来源、外部号、内容摘要、处理结果和业务对象引用。同键不同内容产生显式冲突；网络超时后按原键查单。跨存储发布应先确认文件持久，再发布其数据库引用；回收须验证没有有效引用。

## 集成契约

客户端提交设备、客户端消息号、会话和载荷；同步返回下一游标及缺口。对象附件经授权签发短期读取凭据。

发送输入租户、会话、客户端消息号与媒体引用，输出服务端序号；结果未知按客户端号查原记录。

历史同步提交设备游标、页大小与会话，返回序号区间、下一游标、保留期外缺口和可读取范围。

在隔离环境恢复 MySQL 和引用清单，校验样例的源对象、派生关系及最终结果。恢复后应能回答以下问题。41 只展示一次，新消息 42 依序补齐，两端已读游标最终一致；退群后的新消息对原成员不可见。
