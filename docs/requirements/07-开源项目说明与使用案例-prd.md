# 分布式即时通信平台｜开源项目说明与首个案例

**messaging-cluster** 是面向自托管的 Go 项目。提供长连接网关与消息同步协议，文本历史由 MySQL 持久化，媒体单独存放。 本页作为后续公开使用手册的需求稿，实际发行时补入测试版本、安装入口与已验证的依赖组合。

## 准备

两个网关、三个账号、双设备客户端与本地附件服务。

甲在手机和电脑登录，与乙组成群聊；A 网关接收第 41 条消息后掉线，手机从游标 40 重连。

## 第一次使用

1. 甲在两个设备登录，甲乙入群，记录两设备已同步到的序号 40。
2. 发送新消息，网关持久接收序号 41 后人为断线并重送同一客户端消息号。
3. 重连另一网关并补拉，随后发送序号 42，分别对照消息身份和两端已读水位。
4. 乙退群后发下一条消息，以乙身份尝试拉取新正文与附件并记录拒绝结果。

## 对照综合样例

41 只展示一次，新消息 42 依序补齐，两端已读游标最终一致；退群后的新消息对原成员不可见。 对照结果时保留源记录号、版本和操作时间，追踪从输入到最终交付的关联。

## 制造一次可恢复的异常

游标早于保留窗口时明确展示缺失区间。回到对象详情核对 inbox 和审计记录，再按指定版本恢复或重试。确认相同操作不会生成两份有效结果。

## 自托管与反馈

入群可见历史按群规则冻结；退群后停止新增消息分发，媒体下载也重验当前资格。 提交问题请提供版本、最小合成输入、预期与实际结果。对接扩展可从以下方向开始：客户端 SDK、媒体适配器和通知扩展；提交断线、重复与乱序向量。
